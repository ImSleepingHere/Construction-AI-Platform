## Step 1 -- Meeting Intelligence

`POST /agents/meeting_intelligence`

```json
{
  "input": {
    "notes": "Weekly coordination meeting, Khobar School Project 1.\n\nAttendees: Site PM, Procurement Lead, QA/QC Manager.\n\nRebar delivery from Risk Supplier 001 is now 25 days behind the promised date, holding up the foundation pour on Block B. Procurement flagged this is the third late delivery from this supplier in the last two months.\n\nDecision: switch the remaining rebar packages to a backup supplier in the Concrete category if Risk Supplier 001 cannot commit to a firm delivery date by end of week. Procurement Lead to own this and report back Friday.\n\nAlso raised: QA flagged a workmanship NCR on Risk Supplier 001's most recent delivery batch (surface finish out of tolerance). QA/QC Manager to track through to closure.\n\nRisk: continued delay pushes the foundation pour past the concrete subcontractor's booked slot, which would cascade into a 2-week schedule slip for Block B.\n"
  }
}
```

Or reference the seeded meeting directly (this reconstructs notes from the
decision on file, which is less rich than the full narrative above but
still produces a real decision + action item):

```json
{
  "input": {
    "meeting_id": 261
  }
}
```

Expect: a decision about switching suppliers, a risk about the schedule
slip, and an action item owned by the Procurement Lead.

## Step 2 -- Supplier Risk

`POST /agents/supplier_risk`

```json
{
  "input": {
    "supplier_id": 1
  }
}
```

Expect: `overall_severity: "high"`, concerns citing real delay days and NCR
counts, a risk_score in the 70-80 range.

Repeat with `"supplier_id": 14` for contrast -- expect a
noticeably lower risk_score and `overall_severity` of "low" or "medium".
